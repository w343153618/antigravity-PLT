# 账号隔离、调账与迁移加固

日期：2026-10-13。基于 `codex/phase3-auth-hardening` 的 `a5bf7e2`。GitHub 仓库现为 [w343153618/codex-PLT](https://github.com/w343153618/codex-PLT)，保持私有。

## 本轮交付

- Android 原有 `MainActivity.java` 的 `FLAG_SECURE` 保留，没有替换已有 Python 客户端的服务地址或协议。
- 三个预置账号 `user`、`dianzhang`、`admin` 向 API 调用方返回 `client`、`manager`、`hq`。本次用户指定初始口令的三份 scrypt 摘要已验证匹配，仓库仍不保存明文口令；已有账号摘要和绑定不会被启动配置覆盖。
- 每个 API 按 HTTP 方法和注册路由声明允许角色；未声明策略的 API 默认拒绝。保留 cookie 会话、登录限流、会话过期、跨来源写请求阻断。
- 客户仅接收本人资料和相关门店、店长；店长仅接收名下客户、存根、对账流水、账单和汇总，包括同店其他店长名下资料的隔离。总部保留审计汇总权限。
- 登录前仅创建登录页面；客户、店长、总部按角色条件创建各自工作台，店长登记弹窗不会出现在客户或总部 DOM 中。退出、会话失效、角色异常会清空已有界面状态，迟到响应不能重新填回其他会话的数据。
- 店长的名下客户表新增“调增”“调减”入口，预选客户与方向、定位到金额字段；按分预览结余，余额不足阻止新核减。记录线下已发生的收支，必填原因，并原子写入余额、追加式审计流水和幂等收据。
- 登记结果因网络或服务器错误未获确认时锁定该笔输入，保留请求体和幂等编号。重试返回原收据；不会因重新点击快捷入口生成另一笔账。即使刷新后余额已变为零，也可确认原来的成功核减。
- 单目录非 root Docker Compose，整个 SQLite 数据目录持久化，生产依赖镜像、健康检查、优雅关闭、一致快照、停服恢复与恢复前留档。

## 未实现的请求

本轮没有新增用于的当日推荐编码发布纠错/实时分发，也没有实现客户一键委托、份数与组合计价、预付扣款下单或待出票任务。现有参考展示与历史核验功能保留；`reconciliationBalance` 继续表示已发生线下收支的事后对账结余，不改为预付资金池。因此本轮不表示原请求六项全部交付。
