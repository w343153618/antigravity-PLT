# Domain docs

本项目采用 single-context 布局。

## 阅读顺序

探索代码、实现功能或审查变更前：

1. 阅读根目录 `CONTEXT.md`，它是领域事实的唯一权威来源。
2. 如根目录存在 `GLOSSARY.md`，读取其中的术语说明；
   术语须与 `CONTEXT.md` 保持一致。
3. 阅读 `docs/adr/` 中与当前任务相关的架构决策。
4. 实现具体功能时，阅读 `SPEC.md` 或对应规格工单。

可选的 GLOSSARY.md 或相关 ADR 不存在时，继续工作。
通过 domain-modeling 在实际需要明确术语或决策时维护它们。

## 命名与业务约束

代码、测试、工单和审查使用 CONTEXT.md 定义的领域名称。
在领域文档中维护业务规则，避免在代理配置中复制一套规则。

出现规格、术语或架构决策冲突时，明确指出冲突来源；
领域事实以 CONTEXT.md 为准，架构决策变更须显式记录。
